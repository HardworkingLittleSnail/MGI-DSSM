## 计算与参数效率

### 统一评测协议

效率比较采用“数据集内统一、跨数据集分表”的设计。所有方法均执行与主实验一致的单步容量预测任务，并使用各自在对应数据集上的正式模型配置；NASA、CALCE 和 TJU 的历史窗口分别为16、64和64，训练 batch size 分别统一为32、128和128，推理 batch size 均为1。该设计既保证同一张表中的方法具有相同任务长度、批量规模和硬件背景，也避免将不同输入长度或不同正式配置产生的参数变化误解为模型本身的优劣。各方法保留原有输入表征，因此输入通道数可能不同，但所有输入均严格来自预测时可观测的历史信息。

全部测试在同一台 NVIDIA GeForce RTX 3080 Ti 12 GB GPU 上以 FP32 运行，软件环境为 Python 3.10.8、PyTorch 2.1.2 和 CUDA 11.8。训练采用 Adam（学习率 $10^{-3}$），预热10步后测量100次完整参数更新，并取3次独立测量的中位数；对波动较大的条目增加至5次。推理预热100次后测量1000次单样本前向传播，并报告中位数与四分位距；异常条目进一步以200次预热和2000次测量复核。训练计时排除数据读取、验证、早停和模型保存。参数量仅统计可训练参数，模型大小为序列化 `state_dict` 的大小，训练与推理峰值显存分别在独立进程中测量。FLOPs 由 `torch.profiler` 对受支持算子统计；GRU、Mamba、FFT及部分物理解码算子可能未被完整计数，因此FLOPs仅作为结构参考，实测延迟是主要运行效率依据。表中统计在线模型核心，不包含 IC2ML 的增量容量曲线构造及本文方法的历史状态初始化等离线处理。

### 结果分析

首先，三张表反映的是同一数据集内部的公平比较，而非跨数据集的绝对排名。模型参数量随正式配置和输入形式变化：例如，PatchFormer 的嵌入维度与历史长度相关，其规模由 NASA 的8.567 K增至 CALCE/TJU 的97.895 K；本文模型也因 NASA 使用更宽、更深的状态演化器而由 CALCE/TJU 的约12.8 K增至26.885 K。CALCE 下 PatchFormer 的97.895 K与作者报告的约97.9 K一致，从侧面验证了复现规模。因而，三表分开报告能够同时保持任务内的统一性和模型复现的真实性。

对 Transformer 类方法而言，参数量并不能直接预测实际延迟。PatchFormer 在 NASA 上参数最少，但分块重组和块内/块间注意力使其推理延迟达到4.166 ms；当窗口增至64时，其参数量和延迟进一步上升。Autoformer 的序列分解、自相关计算和编码器—解码器路径产生较多中间操作，在三个数据集上均表现出较高延迟和显存占用。iTransformer 将变量而非时间点作为 token，当前任务中的变量数较少，因此在三套数据上均取得最低推理延迟（1.451--1.516 ms），说明规则化矩阵运算和 token 数量比参数总量更能决定短序列、batch-1 场景下的速度。

电池专用深度模型呈现出更强的数据依赖性。IC2ML 的高维增量容量表示和多分支融合带来1.699--4.845 M参数及较高显存，但其卷积和矩阵运算具有良好的GPU并行性，推理延迟仍维持在2.310--2.752 ms。BATTER-MoE 在 NASA/CALCE 配置下通过稀疏专家保持较小模型和较低训练显存，但 TJU 正式配置使用更大的专家体系，参数增至5.400 M。RUL-Mamba 在 TJU 上保持较低推理显存，而 CALCE 的长序列状态扫描导致训练时间和训练峰值显存明显上升。这些结果表明，模型规模、激活内存与墙钟时间刻画的是不同的效率维度，不能由单一指标替代。

本文模型的效率来自低维数据驱动状态演化与确定性物理解码的分工。在 CALCE 和 TJU 上，其参数量仅为12.805 K和12.773 K，均为最小；NASA 虽因正式配置采用两层、48维状态演化器而不是参数最少的模型，但仍以0.821 s/100 steps取得最低训练时间。本文方法在三套数据上的推理延迟均排名第二，并在 NASA/CALCE 上取得最低推理显存、在 NASA/TJU 上取得最低训练显存。物理网格计算增加了部分中间张量，因此其延迟略高于 iTransformer；与此同时，容量映射无需由大型神经网络重新学习，使在线核心仍保持紧凑。鉴于 profiler 对循环与部分物理算子的覆盖有限，极低的报告FLOPs不应解释为完整物理解码成本。

总体而言，实验并不声称本文方法在每一个效率指标上都占优，而是验证显式物理约束不必以更大的可训练网络或不可接受的在线代价为代价。跨三套数据的一致结果显示，本文方法能够以12.773--26.885 K可训练参数获得最低训练时间和具有竞争力的batch-1推理速度，在模型紧凑性、运行成本与前述预测性能之间形成稳定折中。该结论限定于在线模型核心；若面向完整系统部署，还应将各方法的数据构造与状态初始化等一次性离线成本单独报告。
